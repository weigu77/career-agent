## 3. 版本详解与选取理由

### 3.1 后端核心框架

#### 🐍 Python 3.11.9

Python 3.11 被推荐作为生产环境的首选 LTS 版本，兼具不错的性能与很好的兼容性。3.11.9 是 3.11 分支的最新维护版本，也是 Windows 平台上最新的稳定版本。

- ✅ **稳定性**：充分验证的 LTS（长期支持）版本
- ✅ **性能**：3.11 相比 3.10 有显著性能提升
- ✅ **兼容性**：所有主流第三方库均已稳定支持

> ⚠️ Python 3.14 和 3.15 虽已发布预发布版本，但部分第三方库尚未完全兼容，暂不推荐在生产环境中使用。

#### ⚡ FastAPI ≥ 0.136.1

截至 2026 年 4 月，FastAPI 稳定版本为 0.136.1+，已全面支持 Pydantic v2 的弃用警告并保持与 Starlette 1.x 的兼容性。

```bash
# requirements.txt
fastapi>=0.136.1
```

#### 🚀 Uvicorn ≥ 0.42.0

Uvicorn 的推荐版本为 0.42.0 以上，最新版本已适配 Python 3.14。在确认兼容性时，建议将稳定版本 `0.42.0+` 固定使用。

```bash
uvicorn>=0.42.0
```

#### ✅ Pydantic ≥ 2.13.1

Pydantic v2 已成为 Python 数据验证的标准方案。截至 2026 年 4 月，最新版本为 2.13.1，已支持 Python 3.14。

```bash
pydantic>=2.13.1
```

**LangChain 包中使用的是 Pydantic >=2.7.4, <3.0.0 的范围，我们选取 2.13.x 正处于此范围内，完全兼容**。

### 3.2 Agent 与 AI 编排

#### 🧩 LangChain ≥ 1.2.14

LangChain 在 2025 年 10 月正式发布了 v1.0 稳定版，目前稳定版本为 1.2.14（2026 年 3 月），包含安全补丁和功能优化。LangChain 是目前 Python 生态中 AI Agent 的默认框架，下载量已超过 OpenAI SDK。

```bash
langchain>=1.2.14
```

#### 🕸️ LangGraph ≥ 1.1.3

LangGraph 团队在 2026 年 1 月发布 1.0.7 版本，进一步强化企业级持久化执行、人在循环干预等特性；3 月又迭代到 1.1.3，新增类型安全流、Pydantic 和 dataclass 强制转换等实用功能。

```bash
langgraph>=1.1.3
```

#### 🔍 LangSmith ≥ 0.13.13（可选，主要用于监控/调试）

LangSmith 自托管版本最新为 0.13.13。LangSmith 可用于监控 LLM 应用的全生命周期，支持日均十亿级 Token 监控能力。

---

### 3.3 数据存储与向量数据库

#### 🧠 Milvus 2.6.11+（主选向量数据库）

Milvus 的最新稳定版本为 2.6.x 系列，2.6.11 于 2026 年 2 月发布，主要增强了查询性能、系统稳定性与安全控制。

> 📌 团队使用注意：本项目使用 Milvus Lite 进行本地开发，部署时可选用 Docker Compose 快速拉起。

- ✅ 原生支持嵌入式数据库（Milvus Lite），无需复杂配置
- ✅ 提供丰富的元数据过滤和动态字段支持
- ✅ 社区活跃，文档完善

> 📌 未来可关注：Milvus v3.0 目标于 2026 年底发布。

#### 🐘 pgvector 0.8.2（备选方案/与 PostgreSQL 集成）

pgvector 0.8.2 于 2026 年 2 月发布，修复了并行 HNSW 索引构建中的缓冲区溢出安全漏洞。

若团队选择使用 PostgreSQL + pgvector 方案替代 Milvus，可使用以下版本组合：
- PostgreSQL 17+
- pgvector 0.8.2

#### 🗃️ PostgreSQL 17+（关系数据库 + 长期记忆）

PostgreSQL 17 是目前较新的 LTS 版本，与 pgvector 0.8.2 配合完成统一存储。

#### 📡 Redis 8.4.1+（缓存与对话记忆）

截至 2026 年初，Redis 稳定版本为 8.x 系列，最新稳定版为 8.4.1+。Redis 8.x 相比 7.x 有大幅性能提升和新的数据结构支持。Redis 在项目中主要用于存储用户画像和最近 5 轮对话窗口。

```bash
redis>=8.4.1
```

### 3.4 前端框架

#### ⚛️ React 19.2.5

截至 2026 年 4 月，React 稳定版本为 19.x（最新补丁 19.2.5）。React 19 自动化了许多过去需要手动完成的任务，是当前 React 生态的主流选择。

```bash
# package.json
"react": "^19.2.5",
"react-dom": "^19.2.5"
```

#### ⚡ Vite 8.0.8+

Vite 8.0 于 2026 年 3 月 12 日正式发布。Vite 8 最重要变化是采用基于 Rust 的 Rolldown 作为唯一的构建工具，显著提升构建性能和开发体验。

```bash
npm create vite@latest
# 或指定版本
npm install vite@^8.0.8
```

> 📌 若想在稳定性和 Rust 性能升级之间做一个偏折中方案，也可选择 Vite 7.3.2 进行过渡开发，后续再升级到 Vite 8。

#### 📦 Zustand 5.0.11+

截至 2026 年初，Zustand v5.0.x 是主流版本，最新补丁为 5.0.11，对 middleware 类型提示进行了改进。Zustand 已逐渐成为 React 的默认状态管理工具。

```bash
npm install zustand@^5.0.11
```

### 3.7 部署与容器化

#### 🐳 Docker Compose 5.1.1+

Docker Compose V2（纯 Golang 编写，与 V1 的 Python 实现区分）稳定版本为 5.x 系列，最新为 5.1.1+（2026年3月发布）。

YAML 配置可使用最新 Compose 规范（版本 3.8+），建议开发环境和部署环境均使用 Docker Compose V2。

```bash
# 验证版本
docker compose version
# 预期输出: Docker Compose version v5.1.1+
```

> 📌 若使用 Docker Desktop，其通常捆绑较新版本，但建议单独确认 Compose 版本不低于 5.x。

## 7. 版本更新建议

- **首次环境搭建**：严格遵循本文档推荐版本，避免版本不一致带来的调试困难
- **生产环境**：固定大版本号，补丁版本可跟随安全更新（如 `~=1.2.14`）
- **依赖检查**：使用 `pip freeze` 或 `poetry` 锁定依赖版本，确保可复现构建
- **定期更新**：每两个月检查一次各依赖的最新补丁版本，重点关注安全修复公告
