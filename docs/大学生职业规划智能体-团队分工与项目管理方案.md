# 大学生职业规划智能体-团队分工与项目管理方案

## 一、总体策略

- **目标**：利用AI编程工具降低编码门槛，快速产出可用模块。
- **原则**：小步快跑，每个迭代产出可演示的增量；重度依赖AI生成代码，但成员必须理解逻辑并进行测试。
- **开发模式**：Vibe Coding + 传统协同 —— 每个人先用AI生成骨架代码，再手工调整集成。

---

## 二、团队角色与任务分配

考虑到基础薄弱，不设专职PM/架构师，而是**每人负责一个相对独立的模块**，同时指定一名技术协调人（稍强一点的同学或轮值）负责集成和解决阻塞。

| 角色                     | 姓名（示例） | 负责模块              | 具体任务                                                                                                | AI辅助工具重点                                               |
| ---------------------- | ------ | ----------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **A. 数据清洗与向量库**        | 同学1    | 招聘数据处理            | 1. 编写脚本清洗1万条JD（去HTML、分字段）<br>2. 调用OpenAI embedding生成向量<br>3. 存入Milvus并测试检索                          | Python（pandas, BeautifulSoup） + Copilot；向量化步骤参考官方demo  |
| **B. 后端API与WebSocket** | 同学2    | FastAPI服务         | 1. 搭建FastAPI项目骨架<br>2. 实现`/chat`、`/upload/resume`、`/jobs/match`、`/feedback`接口<br>3. 实现WebSocket流式推送 | FastAPI官方tutorial + Cursor；WebSocket部分用`websockets`库示例 |
| **C. 画像Agent**         | 同学3    | LangGraph节点1      | 1. 设计用户画像JSON Schema<br>2. 调用LLM从对话中提取结构化信息<br>3. 对接Redis读写画像                                       | LangChain文档 + ChatGPT生成ReAct prompt；Redis用`redis-py`示例 |
| **D. 岗位匹配Agent**       | 同学4    | LangGraph节点2 + 工具 | 1. 封装Milvus检索为工具`VectorSearch`<br>2. 写`SkillExtractor`（用LLM抽取JD中的技能）<br>3. 实现`GapAnalyzer`计算技能差集    | 用`pymilvus`官方示例；技能抽取prompt交给GPT生成                      |
| **E. 规划Agent**         | 同学5    | LangGraph节点3 + 工具 | 1. 实现`CourseRecommender`（mock或调用B站API）<br>2. 实现`CalendarPlanner`生成Markdown计划表<br>3. 对接LLM生成周计划      | `rich`库输出表格；课程推荐前期用固定字典                                |
| **F. 前端界面**            | 同学6    | React + 流式对接      | 1. 搭建React项目（Vite）<br>2. 实现聊天界面、Markdown渲染<br>3. 连接WebSocket显示流式消息<br>4. 简历上传组件<br>5. 反馈按钮          | v0.dev生成组件初始代码；`assistant-ui` 或 `ai` 库简化流式处理           |

## 三、项目管理流程（轻量敏捷）

### 1. 工具
- **代码仓库**：GitHub（私有仓库），分支策略：`main`（稳定）、`dev`（集成）、`feature/xxx`
- **任务跟踪**：GitHub Projects 或 Trello（按“待办-进行中-审查-完成”列）
- **文档协作**：Notion 或 飞书（存放清洗规则、API对接约定、Prompt模板）
- **即时沟通**：微信群/Discord + 每日15分钟站会（线上）

### 2. 迭代计划

| 目标                  | 每人生成物                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 环境搭建 + 数据清洗 + 基础API | A: 清洗后1万条JSONL + Milvus容器运行<br>B: FastAPI返回`{"hello":"world"}`<br>C~F: 各自跑通hello-world代码                                        |
| 向量检索 + 画像Agent单测    | A: Milvus成功查询Top5<br>B: 实现`/jobs/match`（调用A的检索）<br>C: 画像Agent能输出固定JSON<br>D: `VectorSearch`工具可用<br>F: React能调用`/jobs/match`显示列表 |
| Agent串联（无规划）        | C: 完成画像Agent+Redis记忆<br>D: 完成岗位匹配Agent（含技能差距）<br>B: LangGraph编排画像→匹配，返回岗位列表<br>F: 聊天界面展示Agent思考过程                               |
| 规划Agent + 前端流式      | E: 规划Agent能生成学习计划<br>B: 实现WebSocket推送全流程<br>F: 流式显示答案和计划表格<br>全体：端到端跑通“上传简历→对话→匹配→规划”                                           |
| 打磨 + 反馈收集 + 部署      | 所有人：修复bug，写简单文档，打包docker-compose一键启动                                                                                            |

## 五、关键风险与应对

| 风险 | 概率 | 应对措施 |
|------|------|----------|
| 大一同学不熟悉Git，代码合并冲突严重 | 高 | 分配一名同学专门负责解决冲突（轮流），每次合并前先`git pull --rebase`；使用GitHub Desktop图形工具 |
| AI生成的代码质量差，逻辑错误多 | 中 | 强制要求**每段AI代码必须手动运行并添加注释**；每周代码评审重点检查逻辑 |
| 某个模块（如Milvus）环境难配置 | 中 | 使用Docker Compose预置所有服务（milvus/redis/postgres），提供一键启动脚本 |
| 团队成员动力不足，进度落后 | 中 | 拆分足够小的任务（例如“实现一个返回随机岗位的API”），快速获得成就感；每周展示成果互相激励 |
| 对LangGraph/LangChain不熟悉 | 高 | 先放弃LangGraph，用最简单的顺序调用函数实现串联；等核心流程跑通后再重构为图 |

## 六、给大一同学的快速学习路径

| 周末 | 学习内容 | 配套AI实践 |
|------|----------|------------|
| 第1周 | Python基础（函数、类、requests） | 用Copilot写爬虫抓取招聘网站 |
| 第2周 | FastAPI 基础（路由、依赖注入） | 用AI生成CRUD接口 |
| 第3周 | LLM API调用（OpenAI格式） | 写一个简单的聊天机器人 |
| 持续 | Git、Docker基础 | 跟着官方教程操作，AI解释每一步 |

## 七、成功标志（由弱到强）

1. **第2周结束**：每个人都能在自己的模块里打印“Hello world”。
2. **第4周结束**：通过API能返回硬编码的岗位推荐结果。
3. **第6周结束**：端到端对话（前端输入→后端Agent→返回岗位和学习计划）。
4. **第8周结束**：所有功能可用，并能用Docker一键启动演示。
