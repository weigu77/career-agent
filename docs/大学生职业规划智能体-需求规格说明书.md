# 大学生职业规划智能体 - 需求规格说明书

## 文档信息
| 项目名称 | 大学生职业规划智能体 |
|---------|---------------------|
| 版本号 | V1.0 |
| 编制日期 | 2025-04-26 |

---

## 1. 项目背景

当前大学生就业竞争激烈，缺乏对行业岗位真实需求的了解，同时职业规划普遍依赖通用建议，无法获得个性化、基于实时市场数据的指导。本项目旨在构建一个基于大语言模型的智能体系统，结合1万条真实招聘数据，为学生提供**岗位匹配、技能差距分析、学习路径规划**等闭环服务。

---

## 2. 目标用户

| 用户角色 | 典型特征 | 核心需求 |
|---------|---------|---------|
| 在校大学生（大一至大三） | 尚未明确方向，希望了解不同岗位要求 | 探索职业可能性，获取技能提升建议 |
| 应届毕业生 | 有明确求职目标，需要针对性准备 | 岗位匹配、简历优化、面试模拟 |
| 职业规划指导老师（辅助使用） | 需要批量了解学生情况，提供辅导 | 查看学生画像、统计行业趋势 |

---

## 3. 总体功能架构

系统分为四个层次：
- **前端层**：React 聊天界面 + 仪表盘，支持流式交互、简历上传、反馈收集
- **API网关层**：FastAPI 提供REST接口与WebSocket
- **智能体核心层**：LangGraph 编排三个专职Agent（画像、岗位匹配、规划）
- **数据与工具层**：向量库存储岗位数据，各类工具（检索、课程推荐、日历）供Agent调用

## 4. 功能需求

### 4.1 前端功能

| 功能模块 | 详细描述 | 验收标准 |
|---------|---------|----------|
| 对话界面 | 类似ChatGPT的多轮对话，支持Markdown渲染、代码高亮；实时显示Agent的思考/工具调用过程（可选折叠） | 用户可连续提问，历史消息保存；在对话流中看到“正在检索岗位...”等状态提示 |
| 简历上传 | 支持PDF、Word、纯文本格式，上传后自动触发解析（提取专业技能、项目经历、教育背景） | 上传成功后在对话中确认，并将解析结果融入用户画像 |
| 反馈组件 | 每条Agent回答下方带“👍 有用 / 👎 无用”按钮，可选填写原因 | 反馈数据落入后端数据库，用于后续模型微调 |
| 仪表盘（可选） | 展示用户画像雷达图（技能掌握度）、岗位匹配度排行、学习计划进度条 | 数据与对话内容同步更新 |

### 4.2 后端API功能

| 端点 | 方法 | 功能 | 请求/响应示例 |
|-----|------|------|--------------|
| `/api/chat` | POST | 普通对话，返回完整回答 | `{"message": "我想找前端实习"}` → `{"answer": "...", "jobs": [...]}` |
| `/ws/chat` | WebSocket | 流式输出Agent的思考过程和最终答案 | 服务端推送多个text/event-stream帧 |
| `/api/upload/resume` | POST | 上传简历文件，返回解析后的结构化信息 | `multipart/form-data` → `{"skills": ["Python","React"], "major":"计算机"}` |
| `/api/jobs/match` | GET | 快速匹配岗位（无需完整对话） | `?skills=Python,SQL&goal=数据分析` → 返回Top5岗位列表 |
| `/api/feedback` | POST | 提交用户反馈 | `{"message_id": "xxx", "rating": 1, "comment": "..."}` |
| `/api/health` | GET | 健康检查 | 返回200 |

### 4.3 智能体核心功能

系统使用 **LangGraph** 构建多智能体协作流程。

#### 4.3.1 画像Agent
- **输入**：用户当前消息 + 历史会话记忆 + 简历文本（如有）
- **输出**：结构化用户画像（JSON格式），包含：
  - `major`: 专业（字符串）
  - `skills`: 已掌握的技能列表（数组）
  - `weak_skills`: 自认不足的技能
  - `goal`: 理想岗位或行业
  - `constraints`: 时间/地点限制（例如“每周可学习10小时”）
- **行为**：首次对话时从零构建；后续对话中增量更新；支持对历史画像的修正（如用户说“我其实不擅长Java”）

#### 4.3.2 岗位匹配Agent
- **输入**：用户画像 + 用户明确提到的岗位关键词（或无）
- **工具**：`VectorSearch`（从1万条岗位中检索）、`SkillExtractor`（从JD中抽取技能）、`GapAnalyzer`
- **输出**：匹配的岗位列表（Top5），每个岗位包含：
  - 岗位标题、公司名称、来源URL
  - 要求的技能清单
  - 与用户当前技能的差距清单（缺失技能）
- **行为**：若用户未指定岗位，则根据画像中的`goal`或常用技能自动匹配；支持筛选条件（地点、行业、实习/全职）

#### 4.3.3 规划Agent
- **输入**：用户画像 + 差距清单 + 目标岗位名称
- **工具**：`CourseRecommender`（推荐B站/Coursera课程）、`CalendarPlanner`（生成时间表）
- **输出**：周粒度学习计划（Markdown表格），每行包含：日期、学习内容、预计耗时、资源链接
- **行为**：主动询问用户每周可用学习时间；计划可修改（前端交互后回写）

#### 4.3.4 协调流程（LangGraph定义）

```
用户输入 → 画像Agent → 岗位匹配Agent → [若存在差距] → 规划Agent → 最终回答
                ↑              ↓
                └── 记忆存储 ───┘
```
- 条件分支：如果用户明确表示“只想知道岗位信息，不要计划”，则跳过规划Agent。
- 错误处理：任一Agent调用失败时，系统返回兜底回答并记录错误日志。

### 4.4 数据与知识库功能

#### 4.4.1 招聘数据清洗与入库
- 支持输入：1万条原始招聘信息（含HTML标签、公司描述等噪声）
- 处理流程：去除HTML标签 → 分离`职责`与`要求`字段 → 生成结构化JSON → 向量化（OpenAI `text-embedding-3-small`）→ 存入Milvus
- 索引设计：每条岗位对应一个向量，元数据包含：岗位标题、公司名、发布日期、来源URL、行业标签（自动分类）

#### 4.4.2 记忆管理
- 使用Redis存储每个用户的长期画像（按`user_id`）
- 存储用户历史反馈（消息ID + 评分）
- 保留最近5轮对话的上下文（滑动窗口）用于多轮交互

## 5. 非功能需求

| 需求类别 | 具体要求 |
|---------|---------|
| 性能 | 普通对话响应时间 ≤ 5秒（含所有Agent调用）；流式输出首Token延迟 ≤ 2秒 |
| 可用性 | 系统可用性 ≥ 99%（开发环境），支持并发20用户 |
| 安全性 | 用户上传简历不存储原始文件（仅提取文本后删除）；API需鉴权（JWT，简单实现） |
| 可扩展性 | 岗位数据库可增量更新（每月爬取新数据）；Agent工具支持热插拔 |
| 成本 | 使用GPT-3.5-turbo作为默认LLM，GPT-4仅用于最终答案生成；单次对话平均token消耗 ≤ 4000 |

## 6. 技术栈详细清单

| 层次 | 技术选型 | 说明 |
|-----|---------|------|
| 前端 | React 18 + Vite | 组件化开发，使用`assistant-ui`加速聊天界面 |

| 文档解析 | PyPDF2 + python-docx | 提取简历文本 |
| 部署 | Docker Compose | 一键启动前后端+Milvus+Redis |

## 9. 验收标准

1. **功能完整性**：用户可上传简历 → 自动匹配岗位 → 生成学习计划，全流程无人工干预。
2. **数据利用**：岗位匹配结果必须来自真实招聘数据集（展示来源URL）。
3. **对话连贯性**：支持用户追问（例如“第一个岗位的薪资范围？”），Agent能结合上下文回答。
4. **流式体验**：前端能看到Agent依次执行“思考→检索→分析→回答”的过程。
5. **反馈闭环**：用户反馈数据正确落入数据库，且可用于后续分析（如导出CSV）。

## 10. 风险与应对

| 风险 | 影响 | 应对措施 |
|-----|------|---------|
| LLM输出不稳定，技能抽取错误 | 导致规划计划不合理 | 对关键输出（技能清单）增加后处理正则 + 人工校验规则 |
| 1万条数据中某些岗位已过期 | 推荐过时岗位 | 在检索时按`update_date`降权，优先展示近3个月岗位 |
| 多Agent串联延迟过高 | 用户体验差 | 采用流式方式，先返回匹配岗位，后台继续生成计划（用户可选等待） |
| 免费API额度耗尽 | 服务中断 | 预留本地模型（如Llama 3 8B）作为降级方案 |

## 11. 附录

### 11.1 与项目目标的对应关系

- **利用真实招聘数据**：岗位匹配Agent完全基于1万条数据回答。
- **个性化规划**：画像Agent持续记忆，规划Agent根据个人约束生成计划。
- **可交互、可反馈**：React前端 + 反馈收集模块。
- **技术栈落地**：FastAPI、LangChain/LangGraph、RAG完全覆盖。

### 11.2 后续扩展方向（不在本版本范围）

- 模拟面试Agent：根据目标岗位生成面试题并评判用户回答。
- 简历自动改写：基于用户画像和目标岗位JD，生成优化后的简历要点。
- 校招日历提醒：自动抓取目标公司的招聘截止日期，主动推送。
- 小组学习功能：匹配有相似职业目标的学生组成学习小组。
